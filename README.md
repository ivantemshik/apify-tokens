# Автоматизация регистрации Apify

Локальное CLI-приложение на Node.js: список готовых почтовых ящиков → браузерная регистрация → API решения reCAPTCHA → письмо подтверждения → создание API-токена → шифрованное сохранение → проверка токена через Apify API.

## Текущий статус

**Сквозной сценарий проверен на настоящем Apify.** В последнем прогоне 21 ноября 2026 года получены пять новых токенов из пяти, каждый повторно проверен через API и выгружен в TXT/JSON. Предыдущая партия из трёх токенов сохранена отдельно. Это подтверждает работу проверенного сценария, но не гарантирует бесперебойность при изменениях интерфейса или большем объёме.

Поддержана почта из существующего проекта `pochti`: Postfix принимает письма, SQLite хранит их на VPS, Telegram-бот показывает пользователю. Основной адаптер читает эту базу через SSH в режиме `mode=ro`, с `PRAGMA query_only=ON`. Отдельные служебные скрипты создают новые ящики штатным методом `Store.issue_address`: они добавляют записи в базу, сохраняя код, конфигурацию и состояние Telegram-бота. SSH-ключ и known_hosts используются из локального каталога `POCHTI_PROJECT`.

Проверенный путь: новый почтовый ящик → email и пароль → reCAPTCHA через 2Captcha → имя профиля → ссылка подтверждения из письма → Settings / API & Integrations → новый персональный API-токен → шифрованное сохранение → проверка `GET /v2/users/me`. Последняя партия потребовала пять CAPTCHA-задач общей стоимостью $0.01495. Секреты, почтовые адреса, браузеры, журналы и экспорты исключены из Git; в репозитории находятся исходники и примеры конфигурации. Ротация отпечатков Fingerprint Suite пока не внедрена.

## Быстрый запуск в PowerShell

Нужен Node.js с поддержкой `--env-file-if-exists`; проверенный runtime — Node.js 24. Команды выполняются из папки проекта. `package-lock.json` фиксирует установленные версии зависимостей.

```powershell
npm.cmd ci --ignore-scripts
npm.cmd run browser:install
npm.cmd run init
```

Откройте `.env` локально и заполните параметры подключения. `init` создаёт случайный ключ `VAULT_KEY`, не меняет существующий `.env` и не печатает ключ в консоль. Сохраните резервную копию ключа отдельно: без него восстановить хранилище нельзя.

```powershell
npm.cmd run check
npm.cmd start
npm.cmd run status
```

`check` проверяет обязательные параметры, ключ и ненулевой баланс решателя, доступность чтения каждого ящика и запуск Chromium. Он не регистрирует аккаунты и не создаёт платные CAPTCHA-задачи. `start` обрабатывает адреса последовательно, без интерактивных вопросов. При незаполненных настройках он завершается с `SETUP_REQUIRED`.

## Решение капчи

В `.env` выбирается готовый сервис:

```dotenv
CAPTCHA_PROVIDER=2captcha
CAPTCHA_API_KEY=YOUR_LOCAL_KEY
```

Альтернатива: `CAPTCHA_PROVIDER=capsolver`. Программа использует `createTask` и опрос `getTaskResult`. Поддержаны reCAPTCHA v2, Invisible v2 и v2 Enterprise: чтение sitekey, дополнительных параметров, заполнение response-поля и вызов callback. Для v3, Turnstile и других типов отдельный адаптер не реализован.

По умолчанию не более двух платных задач на аккаунт за запуск. Создание платной задачи не повторяется при сетевой ошибке: первая задача могла уже быть оплачена. Дополнительно `CAPTCHA_TOTAL_BUDGET_USD` включает постоянный журнал `CAPTCHA_BUDGET_FILE`: перед каждой задачей резервируется $0.01, резерв не освобождается после ошибок или повторного запуска, а фактическая стоимость записывается отдельно. Отдельный файл журнала используется для каждой новой партии. Получение ответа решателя не гарантирует его принятия сайтом.

Свой сервис распознавания не разрабатывался. Ключи решателя и почты не передаются в Apify; решателю передаются параметры CAPTCHA и адрес страницы. API-токен Apify используется для проверки только на `api.apify.com`.

## Почтовые ящики

### Подключённый проект pochti

Для этого адаптера задайте `MAIL_PROVIDER=pochti` и параметры своего сервера в локальном `.env`. Основной CLI использует OpenSSH с проверкой существующего отпечатка сервера и чтением базы. На VPS запускается одноразовый Python-код из проекта Apify без записи исходников и без создания `__pycache__`. Служебные скрипты выдачи адресов отдельно вызывают штатный механизм создания ящиков и меняют данные почтовой базы.

```powershell
npm.cmd run mail:check
npm.cmd run mail:sync
```

`mail:check` проверяет активность адресов независимо от ключа решателя. `mail:sync` заменяет локальный `accounts.jsonl` списком действующих адресов владельца `POCHTI_ANCHOR_EMAIL` и сохраняет настройки уже известных адресов. Истёкшие ящики не импортируются. Команда не создаёт адресов и не меняет серверную базу. Встроенный срок жизни этих ящиков — 24 часа; перед новым пакетом регистраций обновите список. Если исходный ящик уже удалён по сроку, укажите в `POCHTI_ANCHOR_EMAIL` другой свой существующий адрес.

Параметры для переноса на другой компьютер:

```dotenv
MAIL_PROVIDER=pochti
POCHTI_PROJECT=C:/path/to/pochti
POCHTI_SSH_HOST=root@mail.example.com
POCHTI_REMOTE_CONFIG=/etc/tempmail/config.json
POCHTI_ANCHOR_EMAIL=YOUR_EXISTING_MAILBOX
```

По умолчанию ключ берётся из `.secrets/sprintbox-maintenance`, отпечаток — из `.secrets/sprintbox-known-hosts` внутри `POCHTI_PROJECT`. Они не копируются в Apify. Можно переопределить пути переменными `POCHTI_SSH_KEY` и `POCHTI_KNOWN_HOSTS`.

`accounts.jsonl`: одна JSON-запись на строку. Для основного CLI ящики должны уже существовать. Создание новых адресов выполняется отдельными служебными скриптами.

```json
{"email":"first@example.com","mailPasswordEnv":"MAIL_PASSWORD_FIRST"}
{"email":"second@example.com","mailPasswordEnv":"MAIL_PASSWORD_SECOND"}
```

Значения переменных `MAIL_PASSWORD_FIRST`, `MAIL_PASSWORD_SECOND` задаются в `.env`. Если у всех адресов один catch-all ящик, можно использовать общий `IMAP_USER` и `MAIL_PASSWORD`. Для отдельного логина доступно поле `mailUser`. Пароли не пишутся в JSONL-файл.

### IMAP

```dotenv
MAIL_PROVIDER=imap
IMAP_HOST=imap.your-mail.example
IMAP_PORT=993
IMAP_FOLDER=INBOX
IMAP_USER=
MAIL_PASSWORD=YOUR_LOCAL_PASSWORD
```

Используется IMAP с TLS с начала соединения (обычно порт 993), проверкой сертификата и доступом только для чтения. Пустой `IMAP_USER` означает вход под адресом текущего аккаунта. Если письма попадают в Spam, задайте соответствующую папку в `IMAP_FOLDER`.

### HTTP API

Для собственного почтового backend поддержан следующий контракт:

```dotenv
MAIL_PROVIDER=http
MAIL_API_URL=https://mail.your-service.example/messages?email={email}
MAIL_API_TOKEN=YOUR_LOCAL_KEY
```

GET-запрос подставляет URL-кодированный email и, если указан ключ, добавляет `Authorization: Bearer ...`. Перенаправления запрещены. API должен вернуть массив писем либо объект `{"messages":[...]}`:

```json
{
  "messages": [
    {
      "to": "first@example.com",
      "from": "Apify <noreply@apify.com>",
      "date": "2026-11-19T12:00:00Z",
      "text": "...ссылка из настоящего письма...",
      "html": "...необязательный HTML..."
    }
  ]
}
```

Для другого формата API нужно изменить адаптер `src/mail.js`. Встроенного API для `kurilka365.ru` нет. Программа проверяет получателя, дату, домен отправителя и точный hostname ссылки подтверждения. Сейчас разрешены ссылки `console.apify.com` и `api.apify.com` с путём подтверждения; ссылки через почтовые трекеры требуют отдельной проверенной обработки.

## Токены, состояние и восстановление

Пароли аккаунтов генерируются автоматически и сохраняются перед регистрацией. Пароли, токены, адреса и состояния лежат в `data/accounts.vault.json`, зашифрованном AES-256-GCM. Ключ хранится в локальном `.env`. Не публикуйте эти файлы вместе. На Windows права доступа наследуются от папки: режим файла не заменяет ACL Windows.

Токен сохраняется сразу после обнаружения, затем проверяется через `GET https://api.apify.com/v2/users/me`, включая совпадение email. Статус `done` означает, что проверка прошла. Сохранённые токены повторно не выпускаются. Уже готовые аккаунты пропускаются. Создаётся персональный токен с настройками доступа формы Apify по умолчанию; настройка ограниченных прав в этом прототипе не реализована.

Повторный запуск использует прежний пароль и пытается войти. Если предыдущий запуск прервался при самом создании токена до его сохранения, статус `token_creating` требует сверки в Apify Console: ещё один токен автоматически не создаётся. Если подтверждено, что регистрация не состоялась, можно явно разрешить повтор с прежним паролем:

```powershell
node --env-file=.env src/cli.js retry-signup first@example.com
```

Один vault защищён файлом `.lock` от одновременной записи. После аварийного завершения удалять `.lock` следует только убедившись, что другой экземпляр программы не работает.

Экспорт проверенных токенов в новый незашифрованный JSON-файл:

```powershell
npm.cmd run export -- exports/tokens.json
```

Существующий файл экспорта не перезаписывается. В обычных логах нет паролей, токенов и сырых ответов сервисов.

`RUN_TARGET_TOKENS` задаёт целевое количество проверенных токенов среди адресов выбранного `ACCOUNTS_FILE`; готовые аккаунты учитываются, после достижения цели цикл останавливается.

## Служебные скрипты

Каталог `scripts/` сохраняет использованные при боевых прогонах инструменты: выдачу адресов, создание партий, повторную проверку и экспорт. Эти скрипты привязаны к конкретному развёртыванию `pochti` и историческим файлам в `data/` и `exports/`. Эти файлы намеренно не публикуются. Скрипты не являются готовой точкой входа для чистого клона: сначала настройте своё развёртывание и подготовьте локальные манифесты. Для обычного запуска используйте основной CLI и свой список `accounts.jsonl`.

## Интерфейс Apify и проверки

Если Apify изменит форму, скопируйте `selectors.example.json`, измените селекторы и задайте `SELECTORS_FILE` в `.env`. Для наблюдения за запуском установите `HEADLESS=false`. Дополнительные обязательные поля, телефонная проверка, необычный onboarding и отличающийся механизм выдачи CAPTCHA могут потребовать изменения `src/browser.js`.

```powershell
npm.cmd test
npm.cmd run test:browser
```

Модульные тесты проверяют шифрование и целостность хранилища, блокировки, количество платных задач, сетевые ошибки, принадлежность токена и отбор писем. Браузерные тесты выполняют сценарий на контролируемых HTML-страницах с перехватом всех запросов, включая callback CAPTCHA и немедленное сохранение токена. Они не подтверждают совместимость со всеми шагами живой формы Apify и не используют настоящий CAPTCHA API.

Локально прошли модульные тесты и 3 браузерных сценария, включая SSH-адаптер, обработку истёкших адресов, формат писем pochti и ссылки в квадратных скобках. Playwright, почтовые библиотеки и Chromium установлены в проекте. После переключения на 2Captcha предварительная проверка `npm run check` проходит; параметры IMAP и пароль почты для выбранного адаптера не требуются.

Официальные источники: [регистрация Apify](https://docs.apify.com/account/console), [токены Apify](https://docs.apify.com/integrations/api), [CapSolver](https://docs.capsolver.com/en/guide/captcha/ReCaptchaV2/), [2Captcha](https://2captcha.com/api-docs/recaptcha-v2), [ImapFlow](https://imapflow.com/docs/api/imapflow-client/).
